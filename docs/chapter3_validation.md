# Chapter 3: Dataset Validation and Data Leakage Resolution

## Data Leakage Check Output

### Root Cause Analysis

On Windows (case-insensitive NTFS filesystem), `glob("*.jpg")` and `glob("*.JPG")` match the same files. Files with `.JPG` extension (e.g., `Tomato_healthy_001.JPG`) were matched by both glob patterns, resulting in duplicate `Path` objects in the image list. After `random.shuffle`, the same physical file could be assigned to different splits (train/validation/test), creating data leakage.

### Verification Results (Before Fix vs After Fix)

| Metric | Before Fix | After Fix |
|--------|-----------|-----------|
| Total images | 29,103 | 19,849 |
| Train split | 20,372 | 13,907 |
| Validation split | 4,365 | 2,971 |
| Test split | 4,366 | 2,971 |
| Cross-split duplicate filenames | 9,254 | **0** |
| Per-class val minimums met | Partially met | Met |
| Per-class test minimums met | Partially met | Met |

### How Extra Images Were Made

The 9,254 extra entries were duplicate file paths generated by overlapping glob patterns. For example, a file `Tomato_healthy_001.JPG` would appear:

- Once from `glob("*.jpg")` - returned as `Path(".../Tomato_healthy_001.JPG")`
- Once from `glob("*.JPG")` - returned as `Path(".../Tomato_healthy_001.JPG")`

Python's `Path` objects with different construction paths but identical filenames were treated as distinct entries, causing the same file to be counted twice and potentially placed in multiple splits.

### Fix Applied

```python
# scripts/split_dataset.py (lines 79-90)
seen = set()
images = []
for pattern in ("*.jpg", "*.JPG", "*.png", "*.PNG", "*.jpeg", "*.JPEG"):
    for path in src_class_dir.glob(pattern):
        key = path.name.lower()
        if key not in seen:
            seen.add(key)
            images.append(path)
```

The `seen` set uses `path.name.lower()` as the key, ensuring case variants of the same filename (e.g., `tomato_healthy_001.jpg` vs `Tomato_Healthy_001.JPG`) are only counted once.
